# ADR 0005: animate-ui dropdown primitive for toolbar pickers

- Status: accepted
- Date: 2026-10-10
- Context: The chart toolbar's metric and range pickers went through two shapes in two days — segmented pills (which can't share one phone row without stacking or overflowing) and native `<select>`s (correct, but no motion feedback on a control advertisers flip repeatedly). The team asked for the animate-UI Radix dropdown primitive (`pnpm dlx shadcn@latest add @animate-ui/primitives-radix-dropdown-menu`): the Mint pill springing between items ties the pointer position to the selection, which a flat select can't show. The motion must be decoration only — Radix supplies the interaction (arrow keys, typeahead, Escape, focus management).
- Decision: Install the primitive via the shadcn CLI (`components/animate-ui/primitives/radix/dropdown-menu.tsx` + `effects/highlight.tsx`, plus `hooks/use-{controlled-state,data-state}.tsx` and `lib/get-strict-context.tsx`). `motion` was already a dependency (Sidebar); `radix-ui` `^1.7.0` (the unified package, not `@radix-ui/react-*`) is new. Created `components.json` for the CLI — new-york style, hugeicons, no CSS-variable theme: this project themes with Tailwind v4 `@theme` tokens (naija/pine/mint/mist…), not shadcn's `--background` set, so installed components get token classes at the wrap site, never vendor CSS variables.

  Features never import the primitive directly. `components/ValuePicker.tsx` is the one wrap: labelled 44px trigger showing the current value plus chevron, menu on the 14px card radius with a Mist border and no shadow, `menuitemradio` items, Naija Green tick on the current value (colour is never the only signal), Mint highlight pill (`mode="parent"`), `modal={false}` so the page keeps scrolling while a menu is open, and `MotionConfig reducedMotion="user"` at the caller. Form fields (ProfileForm, CampaignForm, CreativeUploader) keep the native `<select>` — radio-item menus are not form controls: no FormData value, no label association, worse mobile keyboards. If a form ever needs an animated select, it's the Radix *select* primitive (hidden input) through this same ADR process, not a dropdown menu.

  Three lint fixes landed in the installed files to keep `pnpm lint` green: controlled `useControlledState`/`Highlight` sync now adjusts state during render (React's derived-state pattern) instead of `setState` in an effect, and the item observer callbacks read a hoisted ref instead of closing over a `const` still in its temporal dead zone. Formatting follows the repo prettier config.
- Consequences: Two dropdowns in the app, one pattern. `motion` and the React-compiler lint rules (`react-hooks/set-state-in-effect`, `react-hooks/immutability`) are now load-bearing: registry installs must be assumed lint-dirty and fixed before commit. Remaining UI kits still need an RFC; this ADR covers one component, not the animate-ui catalog.
